# awrit — `awrit-native-rs` Package Resolution Failure

**Date**: 2026-08-30
**Bun version**: (local `.bun` install)
**Platform**: Linux x86_64

## Symptom

Running `./awrit` fails immediately with:

```
Cannot find package 'awrit-native-rs' from '/home/gilles/DEVELOPPEMENT/REPOS/awrit/src/runner/index.ts'
```

The error originates from `src/runner/index.ts:9`:

```ts
import { isTmux } from 'awrit-native-rs';
```

## Root Cause

The failure is caused by two compounding issues:

### 1. Workspace Isolation

`src/runner` is declared as a **Bun workspace** in root `package.json`:

```json
"workspaces": ["src/runner"]
```

Workspaces have their own `package.json` and are isolated — they do **not** automatically inherit the root project's dependencies. The runner's `package.json` does not declare `awrit-native-rs`:

```json
// src/runner/package.json — missing awrit-native-rs
{
  "dependencies": {
    "solid-js": "^1.9.9",
    "tailwindcss": "^4.1.12"
  }
}
```

### 2. Broken `file:` Dependency Copy

The root `package.json` declares `awrit-native-rs` as a local `file:` dependency:

```json
"awrit-native-rs": "./awrit-native-rs"
```

When `bun install` processes a `file:` dependency, it **copies** the source directory into `node_modules/` rather than symlinking it. The copy is filtered through `.npmignore`.

#### Evidence

| Artifact | Source (`awrit-native-rs/`) | Copy (`node_modules/awrit-native-rs/`) |
|---|---|---|
| `index.js` | Present (29.5 KB, NAPI-RS generated) | **Missing** |
| `index.d.ts` | Present (3.1 KB, NAPI-RS generated) | **Missing** |
| `awrit-native-rs.linux-x64-gnu.node` | Present (757 KB) | Present (722 KB — different build) |
| `package.json` | `"main": "index.js"` | Same, but entry point absent |

The diff confirms:

```
Only in awrit-native-rs/: index.d.ts
Only in awrit-native-rs/: index.js
```

The `package.json` declares `"main": "index.js"`, but this file does not exist in the copy. Bun cannot resolve the package entry point, so it reports the package as not found — even though the directory exists.

### Why Are the Files Missing?

`index.js` and `index.d.ts` are generated by the NAPI-RS build step (`bun run make` → `napi build --platform --release && ./run-shim scripts/fix-types.js`). These files were likely generated **after** the last `bun install`, so the copy in `node_modules/` was made without them. The source files are git-tracked (confirmed by `git status` showing them as `modified`), so the `.npmignore` is not the cause.

## Diagnosis Steps

1. Confirmed `node_modules/awrit-native-rs/` exists but has no `index.js` or `index.d.ts`
2. Confirmed source `awrit-native-rs/` has both files (NAPI-RS generated)
3. Confirmed `src/runner/package.json` does not declare `awrit-native-rs` as a dependency
4. Confirmed `src/runner` is a workspace — module resolution starts from `src/runner/` and does not walk up to root `node_modules/` for undeclared dependencies

## Fix

### Approach 1: Convert to Workspace (Recommended)

Make `awrit-native-rs` a workspace member so it is **symlinked** (not copied) into `node_modules/`. Generated files are always visible through symlinks.

**Step 1** — Add to root `package.json` workspaces:

```json
"workspaces": ["src/runner", "awrit-native-rs"]
```

**Step 2** — Add dependency to `src/runner/package.json`:

```json
"dependencies": {
    "awrit-native-rs": "workspace:*",
    "solid-js": "^1.9.9",
    "tailwindcss": "^4.1.12"
}
```

**Step 3** — Reinstall:

```bash
bun install
```

**Trade-offs:**

| Pros | Cons |
|---|---|
| Generated files always visible via symlink | Workspaces have stricter versioning constraints |
| Clean monorepo pattern | Some build tools have issues with symlinked native modules |
| No ordering dependency between build and install | Requires testing NAPI-RS loading through symlinks |

### Approach 2: Add File Dependency to Runner

Declare the dependency in the runner's `package.json` as a relative file path:

```json
"dependencies": {
    "awrit-native-rs": "file:../../awrit-native-rs",
    "solid-js": "^1.9.9",
    "tailwindcss": "^4.1.12"
}
```

**Trade-offs:**

| Pros | Cons |
|---|---|
| Simple change | Still uses copy mechanism — must generate files before install |
| No workspace restructuring | Duplicates the dependency declaration |

### Approach 3: Regenerate Before Install

Ensure generated files exist, then reinstall:

```bash
cd awrit-native-rs && bun run make  # generates index.js + index.d.ts + .node
cd .. && bun install
```

**Trade-offs:**

| Pros | Cons |
|---|---|
| No config changes | Fragile — ordering dependency between build and install |
| | CI/CD pipelines must handle this step |

## Prevention

### Option 1: Pre-install hook in setup.sh

After the native build step, verify the generated files exist:

```bash
NATIVE_DIR="$BASE_DIR/awrit-native-rs"
if [ ! -f "$NATIVE_DIR/index.js" ] || [ ! -f "$NATIVE_DIR/index.d.ts" ]; then
  echo "awrit-native-rs not built, building now..."
  (cd "$NATIVE_DIR" && "$BUN_EXE" run make)
fi
"$BUN_EXE" install
```

### Option 2: Workspace conversion (prevents the issue structurally)

If `awrit-native-rs` is a workspace, symlinks are used and generated files are always visible. No pre-install check needed.

### Recommendation

**Approach 1 (workspace conversion)** is the most robust fix. It eliminates the copy-vs-source mismatch entirely and follows standard monorepo conventions. The risk of symlinked native modules is low — Bun's NAPI-RS support handles symlinks correctly in practice.
